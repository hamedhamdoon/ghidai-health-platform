## Correction semantics and remaining policy dependency

Request intake is optional; it is not an exclusive approval gate or freeze of personal historical logs. Existing `TrackingService.window` skips completed/withdrawn enrollments, so ordinary owner log edits may still proceed under existing validation, revision and RLS rules. Decreasing recorded totals can revoke derived completion/awards. A pending request's encrypted snapshot and expected revision can therefore become stale after an ordinary edit. No exceptional application is enabled, so no stale proposal is applied by the new workflow.

A-03/A-11 must determine the relationship between personal-log changes, closed participation, correction duration and reviewer authority before an operational exception process can be accepted. The intake implementation includes a completed-status branch, but normal join/completion guards prevent generating a genuine historical completed fixture on demand in the present clock. That branch remains NOT TESTED; no trigger was disabled or completion constraint weakened to claim coverage. Withdrawn intake/cancel is directly exercised through a legitimate enrollment and withdrawal.

## Earlier failures retained

Independent review found the initial materialized rule/schema graph was not fully bound to its reviewed document; native guards now check exact fields, complete graph and published pointers. It also found completed/withdrawn closure was skipped in initial correction intake; the intake query now evaluates the covering immutable policy/day directly. Development runs additionally exposed a legitimate reviewer-capability RLS denial, a SQL JSON alias collision and a missing correction-audit policy. These failed runs remain part of the record and are not passes.

The first new schema/correction browser attempts timed out on exact label-text locators wrapping textarea/select descendants. Accessible-role selectors repaired the tests without increasing 90-second budgets or removing assertions. The final unified replay supersedes those failed attempts. Performance, dependency/container security, backup custody and production operations have separate evidence and may still prevent broader acceptance despite these functional results.
