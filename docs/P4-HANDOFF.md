## الوظائف المنفذة

تأليف البرامج والإصدارات، مدة 1..366 يومًا وبداية مرنة أو ثابتة، تعديل مدة المسودة مع توسيع التكرار، الأيام والمهام والأهداف والأوقات المطلقة والنسبية، معاينة وفحص نشر، ومراجعة مستقلة للمحتوى. الوجبات متعددة المكونات والبدائل والخطط محفوظة فعليًا. النسخ المنشورة ثابتة، والتعديل ينشئ نسخة مستقلة، والسحب والأرشفة مدققان. لا مشاركة أو جدول مستخدم أو P5/P6.

المصادر الست و17 اختلافًا محفوظة كمراجع غير منشورة، والحقوق UNKNOWN. حواجز الهوية والمصدر والاعتماد والثبات تطبق في API وPostgreSQL. التأهيل مستقل عن الدور، ويحفظ دليل حالته وقت القرار داخل سجل مراجعة ثابت؛ لا تمنح fixtures اعتمادًا صحيًا أو حقوقًا إنتاجية.

## التشغيل المحلي

شغّل Docker Desktop وافحص حاويات GHIDAI الحالية والمنافذ أولًا. استخدم الموارد الموجودة، ولا توقف قاعدة tmpfs قائمة لغرض التصفير، ولا تنفذ down/reset/delete/recreate.

```powershell
npm run db:migrate:p4:dev
npm run db:migrate:p4:test
npm run db:generate
npm run sources:p4:dev
npm run fixtures:p4:dev
npm run dev
```

التطبيق http://127.0.0.1:3000 ومساحة التأليف /admin/programs. أداة fixtures تقبل development فقط، وتكتب حسابين اصطناعيين وكلمات مرور عشوائية في ملف .env.p4.fixtures-*.local مستثنى من Git. لا تطبع الأسرار أو ترفعها. الأول ADMIN للتأليف والثاني COACH للمراجعة المستقلة؛ capability والتأهيل ساعتان فقط. الحساب العادي لا يحصل على هذه الصلاحيات.

سجّل الدخول باستخدام الملف المحلي. جهّز MFA من /account/security وأكد الهوية قبل النشر أو السحب؛ يجب أن يكون عامل MFA مفعّلًا حاليًا، ولا تكفي إشارة تحقق قديمة في الجلسة. أنشئ محتوى اختبار محايدًا، أرسله للمراجعة، اعتمده بالحساب الثاني، ثم أنشئ البرنامج وأيامه ومهامه. فحص المعاينة يوضح الأيام والاعتمادات والمصادر والوجبات الناقصة. المدير ينشر نسخة الاختبار بعد استيفاء الشروط.

## إعادة التحقق

```powershell
npm run check
npm run test:p2
npm run test:p3
$env:GHIDAI_E2E_PORT='3100'
npm run test:e2e # 60 اختبارات انحدار ثم 12P4 بمخططات منفصلة
npm run test:p4
npm run audit:p4
npm run check:secrets
```

لا تغير P3_TEST_SCHEMA أثناء خادم E2E قائم؛ pools تثبت المخطط عند بدء التشغيل. test:p4 ينشئ مخطط p3_test_* جديدًا يشمل migrations P4 للتوافق مع حاجز P3، ويحفظ المخططات السابقة. test:p3 ينشئ مخطط P3 مستقلًا. لا تشغّل اختبار outages بالتوازي مع المتصفح أو عمليات DB.

قاعدة الاختبار tmpfs مؤقتة: كانت متوقفة عند بداية التكليف، ولم يكن سجل migrations موجودًا بعد تشغيل حاويتها الموجودة. لم يحذف Codex مخططات قديمة؛ المخططات المنشأة في هذه الجولة محفوظة أثناء استمرار Docker. لا يعد ذلك إثباتًا لبقاء بيانات tmpfs عبر إيقاف Docker أو اختبار استعادة إنتاج.

## المحجوب والمؤجل

نشر محتوى المصادر الحقيقية، الحصص والأهداف والتحويلات غير المعتمدة، bootstrap المسؤول وتأهيل الأشخاص الحقيقيين واسترداد صلاحيات الإدارة محجوبة. التسجيل العام والخدمات السحابية والنشر العام غير منفذة. مشاركة المستخدم والجدول والتتبع والتحليل والإنجازات والتذكيرات مراحل لاحقة. قارئ شاشة يدوي وجهازان مستقلان وحمل إنتاج وقبول قانوني واستعادة إنتاج لم تثبت. تحذيرات التطوير الخمسة High موثقة؛ فحص اعتماديات التشغيل صفر.

## ما يحتاج اعتمادًا قبل P5

يلزم تكليف مستقل من المالك لبدء P5. سياسة A-03 وانتقالات المشاركة وقفل الأيام المتبقية من RV-10 تحتاج اعتمادًا قبل قبول سلوك مشاركة حقيقي. A-01/A-05 للمحتوى والحصص والأهداف والتحويلات، A-10 للحقوق، وA-12 للمسؤول والمراجعين الحقيقيين تبقى مفتوحة. بقية قرارات المالك تحتفظ بحالتها وتلزم بحسب الجمهور والبيانات والتشغيل. يمكن اختبار آليات مستقبلية اصطناعيًا دون الادعاء أن قيم fixtures سياسات معتمدة.

Git Commit وPush على فرع P4 فقط بعد الفحوص والأسرار. لا دمج main أو force-push أو نشر عام؛ قيم Commit ونتيجة Push الفعلية في تسليم المحادثة.
