# P4 — المحتوى والمراجعة المستقلة

2026-10-12، Asia/Muscat. A-01/A-05/A-10/A-12 وجميع قرارات المالك الأخرى تظل مفتوحة. التأهيل الاصطناعي لا يوثق أهلية مختص حقيقي.

ContentRevision يحمل سلسلة contentKey/version وpreviousRevisionId والمؤلف والنص والتصنيف وcontentHash. إنشاء تعديل بعد الاعتماد ينشئ DRAFT جديدة بلا اعتماد سابق؛ النسخة القديمة وسجل مراجعتها ثابتان. محتوى مستمد من SourceExtract يكون syntheticOnly=false؛ النسخ اللاحقة لا يمكنها استعادة تصنيف اصطناعي بمجرد إزالة روابط المصدر.

## جدول الحالات

| الحالة | المسموح | الحاجز |
|---|---|---|
| DRAFT | IN_REVIEW | المؤلف، If-Match، إعادة hash كامل للمحتوى وروابط المصادر ومكونات الوجبة والخطة/البدائل |
| IN_REVIEW | APPROVED أو REJECTED | مراجع مستقل، تأهيل ACTIVE بالنطاق المطابق وأدلة وانتهاء نافذ، hash مطابق وسبب |
| APPROVED | WITHDRAWN | ADMIN محلي مخول، إعادة مصادقة وMFA، سجل سحب وسبب وتاريخ |
| REJECTED | إنشاء revision جديدة | لا إعادة اعتماد النص المرفوض أو تحريره صامتًا |
| WITHDRAWN | إنشاء revision جديدة | لا إعادة نشر/تعديل تاريخ النسخة |

إرسال المراجعة يجمد النص ومكوناته ومصادره؛ lock الأب يمنع التعديل المتزامن. إنشاء مراجعة يقفل التأهيل FOR SHARE عبر دالة سياسة محدودة ويعيد فحص النطاق والمؤلف ووقت القرار وحالة المحتوى. لا تاريخ قرار مزور في المستقبل أو تأهيل منتهٍ. ContentReview وContentWithdrawal append-only. qualificationSnapshot يحفظ معرف التأهيل ونطاقه وأدلته ومتحققه وصلاحيته وحالته وقت القرار، ويبقى ثابتًا عند تعديل سجل التأهيل لاحقًا. انتهاء التأهيل يمنع قرارات جديدة، ولا يغير حالة اعتماد صحيح سابق بأثر رجعي؛ السحب المسبب للمحتوى يحجب عرض البرنامج المرتبط. لا تنتج P4 استثناءات مشاركات فعلية لأن P5 غير منفذ.

## الغذاء والوحدات

POST `admin/meals`: contentRevisionId/slot/ingredients، مع اسم وفئة الوحدة وكمية موجبة ذات منزلتين عشريتين، G/ML/PIECE/SPOON/HANDFUL، وRAW/COOKED/UNSPECIFIED. الفئة G→MASS وML→VOLUME وPIECE→COUNT متحققة. التحويل بين الوحدات غير متاح بلا معامل معتمد؛ API لا يقبل تصنيع معامل اعتماد من رقم يرسله المؤلف. SPOON/HANDFUL وUNSPECIFIED يحفظان في المسودة لكن يمنعان النشر الدقيق. أمثلة الاختبار كلها اصطناعية ومحايدة.

POST `admin/nutrition-plans`: نص الخطة/اسم/وجبات بأيام وترتيب وبدائل مرتبطة بإصدارات Meal فعلية. رفض البديل الذاتي والمكرر وروابط معرف meal مع approvalRevision خاطئ، بvalidation وFK مركبة. نشر المثال الاصطناعي يتطلب اعتماد نص الخطة والوجبة وكل بديل؛ يحفظ hash مراجعة كامل وروابط ثابتة، ولا يعرض بديلًا مسحوبًا. هذه ليست موافقة على أهداف أو حصص حقيقية.

GET/POST `admin/content`، POST `admin/content/:id/revisions`، GET `content-revisions/:id` وسجله ومصادره، POST submit/review/withdraw. لا requiresReview=false من العميل؛ كل الأنواع تمر بالمراجعة. GET/POST/PATCH `admin/qualifications` محلي فقط، ADMIN غير المراجع مع reauth/MFA، evidenceReference يبدأ synthetic-local:، وصلاحية≤24ساعة. قيد capability مستقل يظل مطلوبًا؛ لا تسجيل عام يمنح دورًا أو صلاحية مراجعة.

## المصادر الست والاختلافات

`npm run sources:p4:dev` يستورد hashes الصور الست من الملفات الأصلية، وأقسام التحليل المعتمد كـSourceExtract موصوفة صراحة بأنها تحليل التصميم السابق وليست OCR جديدة، و17 SourceConflict غير محلول. الحقوق UNKNOWN وrequiresReview=true. النص الأصلي immutable، وروابط ConflictExtract تحفظ الصور المذكورة في كل اختلاف. لا ينشئ البرنامج ContentRevision أو تعليمات منشورة من هذا الاستيراد. شاشة المصادر/API إدارية فقط، ولا تعرض الصور كأصول عامة. الاعتماد الصحي والحقوق وحسم التعارضات يظلان عند المالك والمختص.
