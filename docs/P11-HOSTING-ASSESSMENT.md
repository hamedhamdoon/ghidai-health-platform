2026-10-15, Asia/Muscat. Desk research of official sources only; no signup, card, cloud resource, mail, scheduler or deployment was activated. Baseline: `79752ab2487168fcc4f5141e3e0b290b2f91f718`. ## Decision

**No complete production-appropriate zero-cost combination is approved or demonstrated.** Personal versus commercial use, lawful health-data processing, secure scheduling, independent storage and sender identity remain unresolved. Free quotas are hard operating constraints, not availability guarantees. Do not buy a domain, enter a card, enable paid usage/trials, or bypass authentication to fit a free plan.

## Independent encrypted backups

An owner-controlled existing external disk in a separate physical failure domain is the first candidate: no new service/card/monthly fee, but hardware availability, free space, custody, encryption keys and legal retention are OPEN. A second path on the same disk or Docker volume is not independent. Manual removable/offline rotation avoids installing a permanent scheduler; it requires approved operational responsibility.

Existing Google Drive personal space is a conditional off-site candidate, **not selected or uploaded**. Up to15GB is shared with Gmail/Photos; remaining quota is unknown. Require encrypted logical dump plus authenticated integrity, separate keys, restore rehearsal, approved transfer/residency/processor terms, account recovery/MFA and export method. Consumer account storage location/legal suitability is unverified; do not infer EU residency. No Google One upgrade. [Google shared quota](https://support.google.com/drive/answer/6374270). Provider snapshots alone are not an independent backup. Local mechanism/evidence: [P11 backup](P11-BACKUP-RESTORE.md).

## Future approval evidence; no activation in P11

Before selection, owner/legal/operator must record intended personal/commercial audience; actual Free/no-card plan screenshot; terms/DPA/subprocessor version and chosen processing regions; quotas and thresholds; sender DNS rights; scheduler TLS and retry behavior; independent encrypted storage and recovery custody; measured budget and cutoff behavior. Disable automatic previews/deployments and paid integrations before connecting any future repository. Private GitHub CI quotas require verification; CI is not a production scheduler or a storage archive.

Model a30day budget: users×requests/day, API/job CPU, DB active CU-hours, encrypted exports+indexes+WAL, email account actions/retries, backup size×retention×copies, egress and build minutes. Suggested local alert bands70/85/95% are engineering warning thresholds, not owner-approved capacity/RPO/RTO. At a threshold: pause optional jobs, bound retries, inform operator, preserve records, fail safely; never auto-upgrade or delete important data. A compatible runtime, legal contract, reliable email and independent restore-capable backup must all fit simultaneously. Until demonstrated, zero-cost production remains BLOCKED.

## Memory and storage clarification — official-source follow-up

Verified again on 2026-10-15: Vercel Hobby Node Functions have **2GB RAM/1vCPU default and maximum**. The360GB-hours above is a monthly provisioned-memory allowance, not RAM per function. The function bundle limit is250MB uncompressed; bundle storage is not writable or durable user-data capacity. [Memory configuration](https://vercel.com/docs/functions/configuring-functions/memory), [function limits](https://vercel.com/docs/functions/limitations). Current general limits also list100MB Hobby CLI source upload and23GB build disk; these are deployment/build limits, not persistent runtime storage. [General limits](https://vercel.com/docs/limits). No persistent local writable disk is established; Vercel's current file guide recommends external object storage for writes. **Current Hobby `/tmp` capacity: NOT VERIFIED** from current normative documentation; the often-quoted512MB comes from a2020 maintainer discussion and is not treated as a current guaranteed allowance. Do not depend on temporary files between invocations or assume Blob/additional storage is approved/free. [Current file guide](https://vercel.com/kb/guide/how-can-i-use-files-in-serverless-functions), [historical512MB discussion](https://github.com/vercel/vercel/discussions/5320).

Workers has no durable local filesystem: its Node-compatible virtual `/bundle` is read-only and `/tmp` is request-local, memory-backed and unavailable to subsequent/concurrent requests. Temporary files count against the128MB Worker memory budget; individual file limit128MB is not additional storage. Persistence requires a separately evaluated storage product/adapter; no KV/R2/Durable Objects quota is implicitly approved here. [Official filesystem contract](https://developers.cloudflare.com/workers/runtime-apis/nodejs/fs/). Neon relational storage remains1GB/project and up to8GB compute RAM as listed above; Render Free exact RAM/CPU remains NOT VERIFIED in this assessment, and its ephemeral filesystem offers no durable free disk.

Exact Free storage bytes, attachment/template limits and provider CPU/RAM allocation: **NOT VERIFIED / not customer-provisioned compute**. No contact upload is authorized. [Official plan](https://help.brevo.com/hc/en-us/articles/208589409-About-Brevo-s-pricing-plans). The current transactional-log guide states logs **and email previews are retained indefinitely by default**, with custom retention configurable; accounts exceeding10million events additionally lose events older than24months.
